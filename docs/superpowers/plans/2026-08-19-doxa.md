# DOXA Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a refinery that takes one opinion, has an agent compose a bespoke analysis pipeline for it, gets that plan approved by a human, executes it under full tracing, and strikes a unique dithered specimen plus a forensic certificate.

**Architecture:** A registry of self-describing operators, each declaring its dependencies and which render parameters it can write. A planner agent selects and orders operators into a DAG. A human signs the resulting work order. An executor topologically sorts and runs the DAG with real concurrency, one span per operator. Every operator contributes weighted values to one render parameter vector, which a dependency-free canvas engine turns into a dithered specimen with full attribution back to the assay that shaped it.

**Tech Stack:** Next.js (App Router), TypeScript, Tailwind, SQLite (`better-sqlite3`), Vitest, NEAR AI Cloud for all LLM and embedding calls, Bright Data Scraper Studio, Port, SigNoz.

**Spec:** `docs/superpowers/specs/2026-08-19-doxa-design.md`

## Global Constraints

- All LLM and embedding calls go through NEAR AI Cloud (OpenAI-compatible). Env vars are `NEAR_AI_BASE_URL` and `NEAR_AI_API_KEY`, read as a pair. The app throws at startup if either is missing. Never read `OPENAI_API_KEY`, `OPENAI_BASE_URL`, or `ANTHROPIC_API_KEY` anywhere in this codebase; the shell has a stray `OPENAI_API_KEY` that would silently authenticate against the wrong provider.
- No em dashes or en dashes in any file: code, comments, docs, commits, UI copy. Use commas, colons, parentheses.
- Prose and UI copy follow the writing rules in `~/.claude/CLAUDE.md`: plain words, active voice, no marketing voice, no emoji headers, no AI attribution in commits. A hook rejects commits whose text breaks that word list, so check copy before committing.
- Local git only. Never add a remote, never push, without Karim saying so in the moment.
- `lib/operators/`, `lib/executor/`, `lib/foundry/` import nothing from `next/*` or `react`. They are plain TypeScript so they stay unit-testable and portable.
- Every operator is deterministic given its input except the four that make network calls (`CLAIM-EX`, `EMBED`, `STANCE`, and the two field operators). Deterministic operators get exact-value unit tests, never snapshot tests.
- Node 20+. Package manager: pnpm.

```ts
import { register } from '../registry'
import { words, sentences } from '../../text'
import type { Operator } from '../../types'

export const TOKENIZE: Operator = {
  id: 'TOKENIZE',
  name: 'Token and sentence census',
  wing: 'forensics',
  blurb: 'Counts what there is to work with before anything else reads it.',
  needs: [],
  costUnits: 1,
  estMs: 5,
  estOps: 40,
  touches: [],
  async run(ctx) {
    const w = words(ctx.opinion)
    const s = sentences(ctx.opinion)
    const unique = new Set(w).size
    return {
      id: 'TOKENIZE',
      ops: w.length + s.length + ctx.opinion.length,
      readings: {
        tokenCount: w.length,
        sentenceCount: s.length,
        avgWordLength: w.length ? w.join('').length / w.length : 0,
        uniqueRatio: w.length ? unique / w.length : 0,
      },
      notes: [w.join(', ')],
    }
  },
}

register(TOKENIZE)
```

Test: for `'abc'` the character-code sum is 294, so `signature` is `'2 x 3 x 7^2'`, `factorCount` is 3 and `largestPrime` is 7. The same text always yields the same `seed`; two different texts yield different seeds. `seed` is a non-negative 32-bit integer.

Implementation: `n = sum of charCodeAt over the raw opinion`. Trial-divide `n` by 2 then odd numbers up to `sqrt(n)`, collecting `(prime, exponent)` pairs. Format the signature with `^` only where the exponent exceeds 1, joined by `' x '`. Seed is a separate FNV-1a 32-bit hash of the raw opinion, since the code sum collides too easily to seed a renderer:

```ts
export function fnv1a(s: string): number {
  let h = 0x811c9dc5
  for (let i = 0; i < s.length; i++) {
    h ^= s.charCodeAt(i)
    h = Math.imul(h, 0x01000193) >>> 0
  }
  return h >>> 0
}
```

Contribution: `seed` at weight `1.0`, which is the highest in the system. Nothing else writes `seed`, so the merge is uncontested by design and every specimen is uniquely keyed to its exact text. `ops` is the trial-division iteration count, counted for real.

- [ ] **Step 7: Write `lib/executor/run.ts`**

Call `layer()`, then process layers in order. Inside a layer, run with a promise pool capped at `opts.concurrency`. Per operator:

1. Skip if any id in `needs` is in `failed` or `skipped`. Emit `skip` with `because: 'depends on <id>'` and add to `skipped`. Mark transitively, so a skip cascades.
2. Emit `start`.
3. Race `op.run(ctx)` against a `timeoutMs` rejection.
4. On success, write the result into `ctx.results`, add `ops` to `totalOps`, emit `done`.
5. On failure or timeout, add to `failed`, emit `fail` with the error message. Never write a partial result into `ctx.results`, because a downstream operator reading a half-populated result is worse than one that skips.

Wrap steps 3 through 5 in `opts.span?.(op.id, { wing: op.wing, needs: op.needs }, ...)` when supplied.

- [ ] **Step 7: Write `lib/foundry/render.ts`**

`renderField(params, size)` returns a `Float32Array` of `size * size` values in `[0, 1]`:

1. Place `primitives.count` circle centres according to `primitives.arrangement`. `radial` spreads them evenly on a ring at 0.32 of the size. `grid` lays them on the tightest square grid that holds them. `spiral` uses the golden angle, `theta = i * 2.39996`, radius growing as `sqrt(i)`. `scatter` uses `mulberry32(params.seed)`.
2. Radius per primitive is `size * 0.06 * (0.5 + primitives.sizeBias) * (0.7 + 0.6 * rand())`, from the same seeded PRNG so it stays deterministic.
3. For each pixel, apply a domain warp: `wx = x + warpAmp * size * fbm(x * warpFreq / size, y * warpFreq / size, { seed, octaves })`, and the same for `wy` with an offset seed.
4. Compute the signed distance to the nearest primitive at `(wx, wy)`, then convert to a value by field type. `bloom` is `1 - smoothstep(0, r, d)` summed and clamped, so mass grows outward. `collapse` is the inverse, `smoothstep(0, r, d)`. `lattice` is `abs(sin(d / (size * 0.04 * scale)))`. `fracture` is `bloom` multiplied by a hard step on a second, higher-frequency fbm, which breaks the form into pieces.
5. Apply `field.scale` as a multiplier on all distance terms before the smoothsteps.
6. Apply `frame.fill` as a radial vignette that pulls values to 0 outside a disc of that fraction of the frame, unless `frame.bleed` is true, in which case skip the vignette so the form runs off the edge.

`quantise(field, params, size)` returns a `Uint8Array`:

```
threshold = (bayer(matrix)[y % matrix][x % matrix] + 0.5) / (matrix * matrix)
v = clamp((field[i] - 0.5) * contrast + 0.5 + bias, 0, 1)
level = Math.floor(v * (levels - 1) + threshold) / (levels - 1)
out[i] = level > 0.5 ? 1 : 0
```

- [ ] **Step 7: Write the shared repair loop and `CORROBORATE`**

```ts
export async function fetchWithRepair(collectorId: string, input: Record<string, string>, fields: string[]) {
  for (let attempt = 0; attempt < 2; attempt++) {
    const rows = await triggerCollector(collectorId, input)
    const check = checkRows(rows, fields)
    if (check.ok) return { rows: check.rows, repaired: attempt > 0 }
    if (attempt === 0) await healCollector(collectorId, check.reason)
    else throw new Error(`Scraper ${collectorId} still failing after one repair: ${check.reason}. A human needs to look at this.`)
  }
  throw new Error('unreachable')
}
```

Two attempts, each told exactly why the last one failed, then it stops and calls a human. It never ships a third guess.

`CORROBORATE`: `needs: ['CLAIM-EX']`, `wing: 'field'`, `costUnits: 20`, `estMs: 9000`. Reads the claim and subject, calls `fetchWithRepair`, then makes one `chatJson` call to label each row as supporting or contradicting the claim. Returns `evidence` entries with `source`, `url`, `snippet`, `retrievedAt` and `supports`. `readings` carries `corroborationScore` (supporting minus contradicting, over total), `sourcesChecked`, and `repaired` as `'yes'` or `'no'`. Contributes `palette.ground` at weight `WING_WEIGHT.field * Math.abs(corroborationScore)`: a well-supported claim gets a lighter ground, a contradicted one gets a darker one.

- [ ] **Step 8: Write `PRIOR_ART`**

Same shape. `needs: ['CLAIM-EX']`, `costUnits: 20`, `estMs: 9000`. Searches for the closest existing public statement of the same take, returns its date and source, and computes `originality` as one minus the best match's similarity, using `cosine` from the semantics wing over embeddings of the claim and each candidate. `readings` carries `originality`, `closestDate`, `closestSource`. Contributes `primitives.count` at weight `WING_WEIGHT.field * 0.8`, scaled so an original take gets more primitives than a rehash.
